## 0. 判定口径

| 标记 | 含义 |
|---|---|
| `PASS` | 按步骤执行且符合预期，附证据 |
| `FAIL` | 符合预期之外，附实际输出／截图＋复现步骤 |

## 1. 环境准备（两组，必须都做）

### 1.A 真实目录部署

1. 新建独立测试 profile（不要用现有生产 profile）。
2. `DSH_HOME` 指向**真实目录**（非 junction、非符号链接），例如 `D:\dsh-retest-a`。
3. profile 中 `ui-settings` 保持启用（原报告因它被置 `false` 导致 14 项无法验证）。
4. 记录：DSH Desktop 版本与 build、Windows 版本、`DSH_HOME` 实际路径。

### 1.B junction 部署（对应 P1-B）

1. 另建 `D:\dsh-retest-b-real`，再建 junction 让 home 指向它：
   ```cmd
   mklink /J C:\Users\<user>\dsh-retest-b D:\dsh-retest-b-real
   ```
2. `DSH_HOME=C:\Users\<user>\dsh-retest-b`（即 junction 路径）。
3. 同样启用 `ui-settings`。

### 1.C 备份与升级警示（务必先读）

- 本构建**首次打开会迁移**插件私有库的存储布局（资产目录与 manifest 目录改名为跨平台安全名）。
- **迁移前**备份 `%DSH_HOME%\agent-team-presets\team-skills`（连同 `registry.json`、`bindings.json`）。
- 旧构建（同为 0.1.6 版本号的原始包）**不认识**迁移后的布局：回退时必须**先恢复备份目录**，不能只替换程序包。

## 3. P0-A：Windows 目录名不得含 `:`

**前置**：1.A 环境，干净库（尚无资产）。

| 步 | 操作 | 预期 |
|---|---|---|
| 3.1 | 首次进入「设置 → 团队技能」 | 页面可打开，无错误；库中列出 **2** 项内置技能 |
| 3.2 | PowerShell 检查资产目录 | 无任何目录名包含 `:` |
| 3.3 | 打开 `%DSH_HOME%\agent-team-presets\team-skills\registry.json` | `id` 仍为 `builtin:git-release-hygiene`、`builtin:github-repository-presentation`（逻辑 ID 不变） |
| 3.4 | 对两项各点开详情 | 正文可读，文件清单非空 |
| 3.5 | 用队长调用 `list_team_skills` | 返回 2 项，不是空数组 |

目录检查命令：

```powershell
Get-ChildItem -Recurse -Directory "$env:DSH_HOME\agent-team-presets\team-skills" |
  Select-Object -ExpandProperty Name | Where-Object { $_ -match ':' }
# 预期：无输出

(Get-Content "$env:DSH_HOME\agent-team-presets\team-skills\registry.json" -Raw |
  ConvertFrom-Json).assets | Select-Object id, version
# 预期：两行，id 形如 builtin:<skillId>
```

> 判定：P0-A；若 `TeamSkills.open()` 仍失败，页面和 `list_team_skills` 现在应显示**具体失败原因**，请把原文贴出。
